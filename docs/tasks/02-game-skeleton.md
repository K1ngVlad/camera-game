# Задача 02 — скелет игры

**Цель:** полный проход игры от меню до финала, где все коты пока ведут себя как `static` (видны на своей камере, клик — найден). Работают экраны, переходы, сетка камер, звук «по камерам», диалоги, попап находки, сцена, сохранение и сброс. Настоящие загадки (клаксон, ожидание, УФ, хор) — задачи 03–04; здесь для них готовим только инфраструктуру.

Читать: `docs/game-design.md`, `docs/architecture.md`, `docs/audio.md` (матрица громкости), `docs/ui-style.md`, `docs/cats.md`.

## Ключевые решения

- **Одно игровое поле 1280×720.** Корневой `<div class="game">` фиксированного размера масштабируется целиком (`transform: scale(...)`, letterbox) под окно. Все размеры в CSS и Pixi — в логических пикселях 1280×720.
- **Один Pixi-холст на всё поле**, под слоем React. `PixiHost` растягивается на всё поле 1280×720 (без собственного letterbox — масштабирует общий корень). Слой UI поверх: `pointer-events: none` у контейнеров, `auto` у интерактивных элементов, чтобы клики по котам доходили до холста.
- **Pixi показывает только «живое»:** на экране камер — содержимое кадра камеры в прямоугольнике `CAMERA_VIEWPORT`; на сцене — всю сцену. На меню и в офисе холст пустой (ticker продолжает работать, рисовать нечего).
- **Прямоугольник кадра камеры** — общая константа в `src/app/layout.ts`, ей пользуются и CSS-вёрстка, и `CameraView`: `CAMERA_VIEWPORT = { x: 397, y: 41, w: 838, h: 634 }` (сверить с вёрсткой и поправить одну константу).
- **Все коты в этой задаче — `static`.** Поле `behavior` в конфиге уже имеет правильный тип для каждого кота (`hornReveal`, `wait`…), но пока реализован только `static`, а остальные типы временно делегируют ему (`behaviors/index.ts`: `default → staticBehavior`). Так поток игры проверяется целиком.
- **Игра заканчивается на последнем включённом коте.** В `cats.ts` у кота флаг `enabled`; сейчас включены 1–5.

## Данные (черновые, правятся в `src/data/`)

**Камеры** (`cameras.ts`): 16 камер, сетка 4×4, номер `n` → строка `(n-1) / 4`, столбец `(n-1) % 4`; соседи — по горизонтали и вертикали, функция `neighbors(n)` с тестом. У камеры: `id`, `name`, необязательные `background` (путь к PNG; нет — процедурный) и `props` (подсказка генератору, например `['moon']`). Стартовые открытые камеры: **1, 2, 5**.

Названия: 1 Переулок · 2 Прачечная · 3 Крыша · 4 Парковка · 5 Подвал · 6 Двор с баками · 7 Детская площадка · 8 Рынок · 9 Караоке-бар · 10 Тыквенная грядка · 11 Остановка · 12 Подъезд · 13 Стройка · 14 Причал · 15 Склад · 16 Клуб.

**Коты** (`cats.ts`) — поля из `docs/architecture.md` плюс `enabled`, `camera` (где сидит; у `collect` позже будет список), `tint` (цвет заглушки, пока нет арта):

| id | камера | открывает камеры | открывает инструменты | tint |
| --- | --- | --- | --- | --- |
| drummer | 1 | 3, 6 | horn | `#F4F1E8` |
| longcat | 6 | 7, 10 | — | `#E9A15B` |
| keyboard | 3 | 4, 9 | — | `#9FB4FF` |
| pumpkin | 10 | 11, 13 | uv (выдаётся при **начале** поиска, см. ниже) | `#F28C28` |
| choir | 7 | 8, 12, 14 | — | `#F2B3B8` |
| trumpet, popcat, bongo | 14, 12, 16 | — | — | — (`enabled: false`) |

Инструмент, нужный для поиска кота, выдаётся в момент, когда он становится текущим: поле `grantsOnStart: Tool[]` (у тыква-кота — `['uv']`). Остальные — по находке (`unlocks.tools`).

**Позиции на сцене** (`stagePos`, доли поля): drummer (0.24, 0.92), longcat (0.44, 0.92), keyboard (0.64, 0.92), pumpkin (0.84, 0.92), choir (0.14, 0.62), trumpet (0.34, 0.62), popcat (0.66, 0.62), bongo (0.86, 0.62). Масштаб кота на сцене 0.4.

**Реплики** (`dialogues.ts`): имя помощника — константа `ASSISTANT_NAME = '[Имя помощника]'`. Нужны наборы: `intro` (2–3 реплики завязки + «найди барабанщика»), для каждого кота `onStart` (представить кота, 1–2 реплики), `hints` (3 ступени), `onFound` (1 реплика), `stageUnlocked`, `finale`. Тексты для котов 1–3 и интро — написать живо, по `docs/cats.md`; для 4–5 допустимы короткие черновики, пометить `// TODO text`.

## Поток игры

1. **Меню.** При монтировании запускается `engine.load(...)` (прогресс — тонкая полоска внизу). «Играть» доступна после загрузки; по клику — `engine.start()` (жест пользователя) и `openScreen('office')`. Если есть сохранение — та же кнопка продолжает, плюс «Сбросить прогресс» (с подтверждением в том же UI, без `window.confirm`).
2. **Первый вход в офис без найденных котов** → очередь `intro`. Каждый новый текущий кот → его `onStart` (после закрытия попапа предыдущего).
3. **Клик по коту** (только если `view.clickable`) → `found` пополняется, звук `found`, попап. Закрытие попапа → реплики `onFound` следующего шага: при 3-м коте ещё `stageUnlocked`; после последнего включённого — `finale`.
4. **Сцена** доступна при `found.length >= 3`; после финала остаётся доступной.
5. **Перезагрузка страницы** восстанавливает найденных котов, открытые камеры, инструменты и доступность сцены. Повторно `intro` не показывается (если `found` не пуст).

## Критерии приёмки

- [ ] Полный проход: меню → интро → 5 котов по порядку → сцена открывается после третьего → финальная реплика. Проходится без консоли и перезагрузок.
- [ ] На экране камер звук текущего кота громко на его камере, тихо и глухо на соседней, не слышен дальше; найденные — «из клуба»; на сцене все найденные в полную силу. Переходы без щелчков.
- [ ] Перезагрузка в любой момент сохраняет найденных котов и всё производное; «Сбросить прогресс» возвращает к началу.
- [ ] Камеры визуально различимы, фон одной камеры одинаков между запусками.
- [ ] В StrictMode в DOM один `<canvas>`; переходы между экранами не создают новых Pixi-приложений и не текут (в Performance Monitor число узлов/слушателей стабильно после 20 переходов).
- [ ] Игра вписывается в окно любого размера без прокрутки; клики по коту попадают при любом масштабе.
- [ ] `?dev=1` открывает песочницу.
- [ ] `npm run build`, `npm run lint`, `npm test` — без ошибок.
