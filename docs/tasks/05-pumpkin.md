# Задача 05 — тыква-кот: блэкаут и УФ-фонарик

**Цель:** загадка тыква-кота. Когда он становится искомым, во всём районе гаснет свет: все камеры почти чёрные. Игрок получает УФ-фонарик. Без УФ на камере тыква-кота видно только тускло светящуюся тыкву («источник помехи сам не подвержен помехе»). В УФ кот виден целиком и его можно забрать. После находки свет возвращается.

Плюс подготовка рендера к оставшимся котам: `GameScene` уже ~370 строк, а впереди ещё 4 кота.

Читать: `docs/cats.md` (тыква-кот), `docs/game-design.md` (УФ, глобальные состояния), `docs/architecture.md` (поведения).

## Шаги

- [x] **0. Рендереры котов по поведению.** Вынести отрисовку конкретного кота из `GameScene` в `src/render/cats/`: общий интерфейс

```ts
interface CatRenderer {
  enter(view: CatView, ctx: RenderCtx): void      // кот появился на текущей камере (без анимаций перехода)
  update(view: CatView, prev: CatView | null, ctx: RenderCtx): void   // смена состояния — запуск твинов
  tick(dt: number, ctx: RenderCtx): void           // каждый кадр: амплитуда, твины
  destroy(): void
}
```

  и реализации `StaticRenderer`, `HornRevealRenderer`, `WaitRenderer` (перенос текущего кода без изменения поведения). `GameScene` выбирает рендерер по `behavior.type` и отвечает только за камеру: фон, помехи, сканлайны, оверлеи. Поведение Long Cat и Keyboard Cat после рефакторинга — как было (проверить глазами).

- [x] **0b. Слои кадра камеры** (уточнение оркестратора после ревью шага 0). Сейчас фон, кот и УФ-оверлей лежат в одном `camContainer`, и порядок зависит от того, что добавили последним: кот, созданный после включения УФ, оказывается **поверх** оверлея. Для блэкаута нужен явный порядок. `GameScene` создаёт постоянные слои внутри `camContainer` (фильтр помех остаётся на нём):
  1. `bgLayer` — фон камеры;
  2. `worldLayer` — пропсы и коты (то, что темнеет в блэкауте);
  3. `lightingLayer` — тёмный оверлей блэкаута и фиолетовый УФ-оверлей;
  4. `emissiveLayer` — то, что светится само и не темнеет: свечение тыквы и тыква-кот в УФ.

  `RenderCtx.container` заменить на `RenderCtx.layers: { world: Container; emissive: Container }`; существующие рендереры кладут всё в `world`. Освещение (`updateLighting`) считается в `GameScene` из `worldState` и `session.uv` **на каждой камере**, независимо от того, есть ли на ней кот (сейчас `rebuildCats` выходит раньше, если кот на другой камере — освещение туда не завязывать). Поведение Long Cat и Keyboard Cat не меняется.

- [x] **1. Глобальные состояния мира.** `CatView` получает необязательное поле `world?: { blackout?: boolean }`. Производное `worldState(save, session)` в `progression.ts` берёт его из вида **текущего** кота; тест. `GameScene` применяет его ко **всем** камерам, а не только к камере кота.

- [x] **2. Поведение `uvOnly`** (`behaviors/uvOnly.ts` + тесты). Состояния нет (или пустое). `view`:
  - `world.blackout = true` всегда, пока кот искомый;
  - `catState`: `'dark'`, если `!ctx.uv`; `'lit'`, если `ctx.uv`;
  - `clickable = ctx.uv` (и игрок на его камере — это уже проверяет редьюсер).
  - Клаксон и время на него не действуют.

- [x] **3. Темнота и УФ в кадре камеры.** Слои поверх фона и кота, под плашками:
  - **Блэкаут без УФ:** почти чёрный оверлей (`#05040A`, alpha 0.93). Сканлайны и помехи остаются — камера работает, просто темно.
  - **Блэкаут с УФ:** тёмный оверлей alpha 0.55 + фиолетовая подсветка (`#6E46FF`, alpha 0.3, режим `add` или `screen`, выбрать на глаз). Фон и кот читаются, но выглядят «в ультрафиолете».
  - **УФ без блэкаута** (после находки тыква-кота): только фиолетовая подсветка, как сейчас.
  - Переключение УФ — щелчок `sfx:uv` и плавный переход 0,15 с. Конец блэкаута — оверлей гаснет за 0,8 с.
  - Плашка «УФ-РЕЖИМ» и кнопка УФ уже есть — проверить, что состояние совпадает.

- [x] **4. `UvOnlyRenderer` (тыква-кот).** Свечение — всегда в `emissive`; спрайт кота — в `world` в состоянии `dark` (силуэт alpha 0.06 под тёмным оверлеем почти не виден — поэтому силуэт рисовать в `emissive` с alpha 0.06) и в `emissive` в состоянии `lit`.
  - `dark`: виден только **светящийся слой тыквы** над тёмным оверлеем. Если есть проп `props/pumpkin_glow.png` — рисуется он в позиции тыквы; если нет — заглушка: оранжевый круг (`#F28C28`) с `BlurFilter` (сила ~16) и мягким ядром поменьше. Позиция и радиус свечения — в конфиге кота: `glow: { x: number; y: number; r: number }` в долях размера спрайта (подобрать под реальный арт тыква-кота). Яркость свечения **пульсирует по амплитуде `cam:pumpkin`** (alpha 0.35 + 0.5·a), так что тыкву видно и слышно в такт.
  - Силуэт кота в `dark` — alpha 0.06, чтобы внимательный игрок угадал форму.
  - `lit`: кот виден полностью поверх УФ-слоя (не затемнён), обычная анимация от звука, свечение остаётся. Клик работает.
  - Переход `dark ↔ lit` — плавный, 0,2 с.

- [x] **5. Сюжет и звук.**
  - Звук при старте задаётся конфигом, а не особым случаем в редьюсере: поле кота `onStartSfx?: string` (у тыква-кота — `'blackout'`), эффект выдаётся там же, где реплики `onStart`.
  - Когда тыква-кот становится искомым: `sfx:blackout` (короткий «щелчок рубильника + гул, затихающий вниз»), затем реплики `onStart`, затем помощник выдаёт УФ (`grantsOnStart` уже есть — проверить, что кнопка появляется в этот момент, а не раньше).
  - Офис во время блэкаута тоже затемнён: CSS-фильтр `brightness(0.45)` на фоне офиса (кнопки остаются яркими и читаемыми).
  - После находки: свет возвращается (оверлей гаснет), реплика `onFound` в духе «Наконец-то свет!».
  - Генератор заглушек: добавить `sfx/blackout.wav` и `sfx/uv.wav` (короткий щелчок).
  - Тексты: `onStart` — кто-то вырубил свет во всём районе, но у менеджера есть УФ-фонарик. Подсказки: 1) «Включи УФ — в ультрафиолете видно больше»; 2) «Смотри, где в темноте что-то светится оранжевым»; 3) «Камера 10. Включи УФ и забирай его».

- [x] **6. Сохранение.** Перезагрузка во время поиска тыква-кота: блэкаут на месте, УФ доступен, без повторного `sfx:blackout` и диалога `onStart` (они звучат только при смене искомого кота, а не при загрузке).

- [x] **7. Документация.** `docs/architecture.md`: `CatRenderer`, `world` в `CatView`. `docs/cats.md`: уточнить тыква-кота по факту реализации.

## Критерии приёмки

- [ ] Long Cat и Keyboard Cat после рефакторинга рендера ведут себя как раньше.
- [ ] После находки Keyboard Cat (и закрытия попапа) гаснет свет: звук, все камеры тёмные, офис приглушён; появляется кнопка УФ.
- [ ] Без УФ: на всех камерах темно, на камере 10 пульсирует в такт оранжевое свечение, кота не кликнуть.
- [ ] С УФ: все камеры читаются в фиолетовом свете, на камере 10 кот виден полностью и его можно забрать.
- [ ] После находки свет плавно возвращается; УФ остаётся доступен и просто тонирует картинку.
- [ ] Перезагрузка во время блэкаута — блэкаут на месте, без повторного звука и диалога.
- [ ] Тесты: `uvOnly`, `worldState`.
- [ ] `npm run build`, `npm run lint`, `npm test` — без ошибок.
- [ ] Каждый критерий проверен в браузере; что не удалось — в «Отклонения и решения».

## Вне объёма

УФ-следы лап (это Bongo Cat), хор, трубач, Pop Cat. Положение котов на сцене — решаем отдельно, когда в игре будут все коты.

## Отклонения и решения

- **`glow` не добавлено в `CatConfig`:** позиция свечения тыквы (`CAT_X`, `CAT_Y − VP.h×0.12`, радиус `VP.h×0.07`) захардкожена в `UvOnlyRenderer`. Добавить в конфиг, когда появится реальный арт с известной позицией тыквы.
- **Шаг 6 — только анализ, без изменений кода:** `sfx:blackout` и диалог `onStart` генерируются только в `closePopup` при смене искомого кота. На холодной загрузке `openScreen('office')` не триггерит их (условие `save.found.length === 0` не выполняется). `worldState` и `availableTools` вычисляются из `save.found` в localStorage — блэкаут и УФ восстанавливаются автоматически.
