## Часть B. Система поведений

- [x] **B1. Каркас.** По `docs/architecture.md`:

```ts
interface Behavior<C, S> {
  init(cat: CatConfig, cfg: C): S
  on(state: S, event: BehaviorEvent, ctx: WorldCtx): S
  view(state: S, ctx: WorldCtx): CatView
}

type BehaviorEvent =
  | { type: 'horn'; camera: number }
  | { type: 'cameraChanged'; from: number; to: number }
  | { type: 'screenChanged'; screen: Screen }
  | { type: 'bar' }

interface WorldCtx { screen: Screen; camera: number; uv: boolean }

interface CatView {
  camera: number
  catState: string                  // произвольное имя состояния для рендера: 'hidden' | 'revealed' | 'out' | 'peek' | 'in' …
  clickable: boolean
  props: Record<string, 'shown' | 'hidden'>   // пропсы на камере кота: { bin: 'shown' }
}
```

  - В конфиге кота `behavior` становится объектом: `{ type: 'hornReveal' } | { type: 'wait'; bars: number } | { type: 'static' }` и т. д.
  - В `SessionState` — `puzzle: { catId: CatId; state: unknown } | null`. Инициализируется, когда кот становится текущим (включая загрузку сохранения); сбрасывается при находке и при сбросе прогресса.
  - Редьюсер транслирует действия в события поведения: `horn` → `{ type: 'horn', camera }`; `selectCamera` → `cameraChanged`; `openScreen` → `screenChanged`; `bar` → `bar`. `clickCat` засчитывается только если `view.clickable`.
  - **Часы → игра:** `GameRoot` подписывается на `engine.onBar` и вызывает `dispatch({ type: 'bar' })`. На камерах активные часы — луп искомого кота (уже так в движке).
  - Каждое поведение — чистые функции с тестами Vitest. `static` переписать на новый интерфейс.

## Часть C. Long Cat — `hornReveal`

**Логика.** Состояния: `hidden` → `revealed`.

- `hidden`: на камере кота стоит мусорный бак (`props.bin = 'shown'`), кота не видно, клик не работает.
- Клаксон **на камере кота** → `revealed`: бак исчезает, кот виден и кликабелен.
- `revealed` сохраняется до находки, даже если уйти с камеры (не наказываем игрока).
- Клаксон на других камерах ничего не делает.

**Рендер.**

- Бак — проп `props/bin.png` из реестра; пока арта нет — заглушка `public/assets/placeholder/bin.svg` (простой зелёный бак с крышкой и полосами, тот же стиль контура, что у `cat_a.svg`). Бак стоит на полу кадра там же, где будет кот.
- В `hidden` бак **дрожит по амплитуде `cam:longcat`**: сдвиг по x ±3 px и поворот ±2° от амплитуды, опора у дна. Игрок видит, что внутри кто-то басит.
- Переход `hidden → revealed`: бак плавно исчезает (alpha 1→0 и лёгкое сплющивание, 0,4 с), Long Cat «выскакивает» на его месте (scale 0.6→1.08→1, alpha 0→1, 0,35 с, с задержкой 0,1 с). Анимации — простые твины на ticker, без библиотек; модуль `render/tween.ts` с функциями easing (`easeOutBack`, `easeInQuad`).
- Если игрок входит на камеру, когда кот уже `revealed`, — сразу финальное состояние без анимации.

**Тексты.** `onStart`: Long Cat опять залез в мусорку, его слышно по басу. Подсказки: 1) «Слушай, где басит громче всего»; 2) «Бак во дворе трясётся в такт. Может, его спугнуть?»; 3) «Камера 6, клаксон — и он вылезет».

## Часть D. Keyboard Cat — `wait`

**Логика.** Конфиг `{ type: 'wait', bars: 4 }`. Состояния: `out` → `peek` → `in`, счётчик `bars`.

- Счётчик растёт на каждом событии `bar`, только когда игрок на экране камер **и** на камере кота.
- `bars >= половины` (2 из 4) → `peek`: из-за края кадра выглядывает часть кота (уши и глаз). Это обратная связь «он здесь, жди».
- `bars >= cfg.bars` → `in`: кот заходит в кадр и становится кликабельным.
- Уход с камеры кота (другая камера или другой экран) в состояниях `out`/`peek` → сброс в `out`, счётчик 0. В состоянии `in` кот остаётся (не наказываем за то, что игрок отошёл после успеха).
- Клаксон на камере кота → в любом состоянии сброс в `out`, счётчик 0 (кот пугается). Если он был `in` — убегает.
- Его камерный луп звучит всё время, как у любого искомого кота: игрок слышит, что он рядом.

**Рендер.**

- `out`: кот за правым краем кадра, не виден.
- `peek`: кот сдвинут так, что из-за края видно ~25% (голова), лёгкое покачивание; переход — 0,6 с.
- `out/peek → in`: кот заходит до своей позиции за 1,5 с, «шагает» — покачивание ±4° на каждую долю (`onBeat` или фаза по времени), затем обычная анимация от звука.
- `in → out` (клаксон): быстро убегает за край за 0,4 с.
- Клик работает только в `in`, когда анимация входа закончилась.

**Тексты.** `onStart`: Keyboard Cat очень стеснительный, к незнакомым выходит не сразу. Подсказки: 1) «Он где-то рядом, просто стесняется»; 2) «Не переключайся и не сигналь — дай ему привыкнуть»; 3) «Камера 3. Просто подожди там, и он выйдет».

## Отклонения и решения

- **Браузерная проверка не проводилась** — нет GUI-браузера в среде выполнения. Логика покрыта тестами Vitest (146 тестов), TypeScript компилируется чисто, lint чистый.
- **`walkDone` только в рендере** — `waitBehavior` не хранит `walkDone`; рендер выставляет `sprite.eventMode = 'static'` после завершения tween-анимации входа. Упрощает поведение и убирает дублирование состояния.
- **Flee tween при `in/peek → out`** — вместо немедленного скрытия спрайта при horn-событии, `rebuildCats` обнаруживает предыдущее состояние `prev === 'in' || prev === 'peek'` и запускает tween-убегание (0.4 с) с текущей позиции.
